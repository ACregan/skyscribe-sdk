# Vanilla TypeScript

`@skyscribe-sdk/core` is plain TypeScript with no runtime dependencies. It works in any environment: Node.js, Deno, Bun, browsers, edge functions, or any other JavaScript runtime.

Every framework adapter is a thin wrapper around this package. If your framework isn't listed, or you'd rather manage state yourself, use `@skyscribe-sdk/core` directly.

## Install

```bash
npm install @skyscribe-sdk/core
```

## Fetch a site

```ts
import { fetchSite } from '@skyscribe-sdk/core';

const site = await fetchSite('alice.bsky.social', 'https://alice.bsky.social');

console.log(site.title);
console.log(site.description);
console.log(site.url);        // e.g. "alice.bsky.social"
console.log(site.urlPrefix);  // e.g. "blog" or ""

for (const group of site.groups) {
  for (const article of group.articles) {
    console.log(article.title, article.slug, article.description);
  }
}
```

## Fetch an article

Look an article up by its slug, which is what appears in your URLs:

```ts
import { fetchArticleBySlug } from '@skyscribe-sdk/core';

const { article } = await fetchArticleBySlug(
  'alice.bsky.social',
  'https://alice.bsky.social',
  'my-first-post',
);

console.log(article.title);
console.log(article.description);
console.log(article.content);  // Full HTML
console.log(article.createdAt);
```

If you already have an `ArticleRef`, `fetchArticle` skips the Site lookup. It takes the account and record key (rkey), both found in the ref's AT URI (`at://{did}/site.standard.document/{rkey}`). Take the account from there rather than assuming the site owner's: an article credited to a contributor can live in their account.

```ts
import { fetchArticle, slugFromUri } from '@skyscribe-sdk/core';

const ref = site.groups[0].articles[0];
const article = await fetchArticle(ref.uri.split('/')[2], slugFromUri(ref.uri));
```

<Callout type="warning">
  Don't pass a slug to `fetchArticle`: articles published with current tooling have opaque rkeys like `3mp47vvkh342n`, so a slug only finds very old articles. Use `fetchArticleBySlug` when you have a slug.
</Callout>

Before rendering `article.content`, read [Rendering the HTML](/quickstart#3-fetch-an-article): if you show articles from accounts you don't control, sanitise it first.

## Utilities

```ts
import { slugFromUri, flattenArticles } from '@skyscribe-sdk/core';

// The last segment of an AT URI: the record's rkey
slugFromUri('at://did:plc:abc/site.standard.document/3mp47vvkh342n') // → "3mp47vvkh342n"

// All published articles across all groups, in order
const allArticles = flattenArticles(site.groups);
```

## Cancelling requests

Every fetch function accepts an optional `AbortSignal` as its last argument:

```ts
// On the server: cancel if the visitor navigates away
const site = await fetchSite(author, 'https://alice.bsky.social', request.signal);

// In the browser: cancel on unmount or when parameters change
const controller = new AbortController();
const site = await fetchSite(author, 'https://alice.bsky.social', controller.signal);
controller.abort();
```

<Callout type="tip">
  The framework adapters wire up cancellation for you. You only manage signals yourself when using `@skyscribe-sdk/core` directly.
</Callout>

## Site Analytics

Show the Publication's owner visit figures on its Insights tab in SkyScribe (free, cookie-free):

```ts
// In the browser, once per page
import { loadSiteAnalytics } from '@skyscribe-sdk/core';

loadSiteAnalytics();

// Or print the tag into server-rendered HTML
import { siteAnalyticsScriptTag } from '@skyscribe-sdk/core';
```

Figures only appear once your site serves the Publication verification file. See the [Site Analytics guide](/guides/site-analytics) for that, privacy, and CSP.
