# @skyscribe-sdk/nuxt

A Nuxt 3 module with composables and SEO helpers. Install with `npm install @skyscribe-sdk/nuxt`. See the [Nuxt guide](/frameworks/nuxt) for walkthroughs.

## Module registration

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@skyscribe-sdk/nuxt'],
});
```

Once it's registered, `useScribeSite`, `useScribeArticleBySlug`, `useScribeArticle`, `useScribePublicationUri`, `useScribeDocumentUri`, `articleSeoMeta` and `siteSeoMeta` are available in every component and page without importing them.

<Callout type="warning">
  Use version 1.3.0 or later. Earlier versions, including every `@scribe-atp/nuxt` release, left the composables out of the published package, so they were never auto-imported.
</Callout>

## Composables

### `useScribeSite`

```ts
function useScribeSite(
  author: string,
  publicationUrl: string,
  options?: AsyncDataOptions
): Promise<AsyncData<Site | null, Error | null>>
```

Runs `fetchSite` inside `useAsyncData`, so the Site is fetched during server rendering and reused on the client.

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `author` | `string` | Author handle or DID |
| `publicationUrl` | `string` | The site's canonical HTTPS URL, e.g. `"https://alice.bsky.social"` |
| `options` | `AsyncDataOptions` | Optional. Passed on to `useAsyncData` (`lazy`, `server`, `watch` and so on) |

Returns Nuxt's standard `AsyncData`: `{ data, pending, error, refresh }`, where `data` holds `Site | null`.

---

### `useScribeArticleBySlug`

```ts
function useScribeArticleBySlug(
  author: string,
  publicationUrl: string,
  articleSlug: string,
  options?: AsyncDataOptions
): Promise<AsyncData<ArticleResult | null, Error | null>>
```

Looks an article up by its slug in the Site at `publicationUrl`, inside `useAsyncData`. `data` holds `{ article, uri }`: the article and its AT URI. Since 1.3.0.

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `author` | `string` | Author handle or DID |
| `publicationUrl` | `string` | The site's canonical HTTPS URL |
| `articleSlug` | `string` | The article's slug, as in its URL |
| `options` | `AsyncDataOptions` | Optional. Passed on to `useAsyncData` |

---

### `useScribeArticle`

```ts
function useScribeArticle(
  author: string,
  rkey: string,
  options?: AsyncDataOptions
): Promise<AsyncData<Article | null, Error | null>>
```

Runs `fetchArticle` inside `useAsyncData`, so it fetches by the article's **record key (rkey)**.

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `author` | `string` | Handle or DID of the account the article is stored in |
| `rkey` | `string` | The article's record key |
| `options` | `AsyncDataOptions` | Optional. Forwarded to `useAsyncData` |

Returns `{ data, pending, error, refresh }`, where `data` holds `Article | null`. Don't pass a slug: it only finds very old articles. With a slug, use `useScribeArticleBySlug`.

---

### `useScribePublicationUri` / `useScribeDocumentUri`

```ts
function useScribePublicationUri(author: string, publicationUrl: string, options?: AsyncDataOptions)
function useScribeDocumentUri(author: string, publicationUrl: string, articleSlug: string, options?: AsyncDataOptions)
```

Resolve just the AT URI of a Site or (by slug) an article, inside `useAsyncData`. `data` holds the URI string.

---

### `useSiteAnalytics`

```ts
function useSiteAnalytics(options?: { disabled?: boolean }): void
```

Puts the [Site Analytics](/guides/site-analytics) beacon in the page `<head>` through `useHead`, so it's in the server-rendered HTML. Call it once, in `app.vue`. Auto-imported. `disabled` leaves the beacon out.

## Meta helpers

### `articleSeoMeta`

```ts
function articleSeoMeta(article: Article, site: Site): UseSeoMetaInput
```

Returns an object for Nuxt's `useSeoMeta()`: `title`, `ogType`, `ogTitle`, `ogUrl`, `ogSiteName`, `ogDescription`, `ogImage` (the cover image), `twitterCard`, `twitterTitle`, `twitterDescription` and `twitterImage`. `useSeoMeta` can't set a canonical link or structured data: add those with `useHead`, using `buildCanonicalUrl` and `generateArticleJsonLd`, which this package re-exports.

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `article` | `Article` | The full article object |
| `site` | `Site` | The site object |

```vue
<script setup lang="ts">
import { articleSeoMeta } from '@skyscribe-sdk/nuxt';
import { fetchArticleBySlug, fetchSite } from '@skyscribe-sdk/core';

const route = useRoute();
const [{ article }, site] = await Promise.all([
  fetchArticleBySlug('alice.bsky.social', 'https://alice.bsky.social', route.params.slug as string),
  fetchSite('alice.bsky.social', 'https://alice.bsky.social'),
]);

useSeoMeta(articleSeoMeta(article, site));
</script>
```

Import it from `@skyscribe-sdk/nuxt`.

---

### `siteSeoMeta`

```ts
function siteSeoMeta(site: Site): UseSeoMetaInput
```

Returns `useSeoMeta()` input for a site index or group page. The package also re-exports `buildSiteUrl` and `generateSiteJsonLd` for the canonical link and structured data.

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `site` | `Site` | The site object |
